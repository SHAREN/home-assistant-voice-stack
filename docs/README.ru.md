# Home Assistant Voice Stack — русская инструкция

Это публичный стек голосового ассистента для Home Assistant на базе Pipecat и upstream-проекта pipecat-homeassistant.

Это не форк ядра Pipecat. Схема такая:

1. Pipecat — realtime-фреймворк.
2. kyvaith/pipecat-homeassistant — базовое приложение для Home Assistant.
3. SHAREN/home-assistant-voice-stack — производный стек с дополнительной логикой для физической колонки P610, wake-word, warm standby, диагностикой аудио и исправлениями стабильности.

## Что умеет

- общение с Gemini Live напрямую голос-в-голос;
- настоящий full duplex в браузере и на P610;
- управление Home Assistant через MCP;
- локальное пробуждение по Okay Nabu;
- локальная команда Stop;
- заранее прогретая Gemini Live-сессия;
- сохранение начала команды, если говорить сразу после wake-word;
- пропуск звука активации, если команда продолжается без паузы;
- отдельная быстрая VAD-настройка для P610;
- вывод голоса через pacat/PulseAudio с небольшим буфером;
- полная запись диагностической сессии на 24 часа;
- исправление ложных fatal-сбоев при периодическом idle reconnect Gemini.

## Основные каталоги

- addons/pipecat_assist_proxy — главное приложение Home Assistant.
- addons/p610_mic_monitor — монитор микрофона P610.
- custom_components/pipecat_assist — интеграция Home Assistant.
- lovelace — карточки WebRTC/Pipecat.
- tests — тесты.
- tools — калибровка и диагностика.
- experimental/gemini_live — экспериментальная прямая интеграция, не основной рекомендуемый путь.

## Быстрая установка

### 1. Добавить репозиторий дополнений

Home Assistant > Настройки > Дополнения > Магазин дополнений > Репозитории.

Добавить:

    https://github.com/SHAREN/home-assistant-voice-stack

Установить Pipecat Assist Proxy.

P610 Microphone Monitor нужен только при настройке/диагностике физического устройства.

### 2. Установить интеграцию

Через HACS добавить этот GitHub-репозиторий как пользовательский Integration repository и установить Pipecat Assist.

Либо вручную скопировать:

    custom_components/pipecat_assist

в:

    /config/custom_components/pipecat_assist

После этого перезапустить Home Assistant и добавить Pipecat Assist в Настройки > Устройства и службы.

### 3. Настроить Gemini

Открыть веб-интерфейс дополнения Pipecat Assist Proxy.

В Integrations добавить Google Gemini Live и указать ключ Google AI Studio.

Текущая протестированная модель:

    models/gemini-3.1-flash-live-preview

Название модели у Google может меняться. Нужна модель Gemini Live с нативным аудио.

### 4. Настроить MCP Home Assistant

В обычной установке дополнения используется Supervisor token автоматически.

Основной endpoint:

    http://supervisor/core/api/mcp

Долгоживущий токен Home Assistant вручную обычно не нужен.

### 5. Если Gemini недоступен по региону

В настройках дополнения есть gemini_proxy_url. По умолчанию он пустой.

Можно указать собственный HTTP proxy, который выходит в регион, где Gemini Live доступен.

Никакой личный proxy или пароль не должен попадать в GitHub.

## Настройка P610

Сначала убедиться, что Home Assistant хост видит P610 как устройство захвата и воспроизведения.

Затем включить в настройках Pipecat Assist Proxy:

~~~yaml
p610_local_audio: true
p610_flow_id: home-default
p610_wake_threshold: 0.6
p610_stop_threshold: 0.5
p610_refractory_seconds: 2.0
p610_stop_guard_seconds: 0.5
~~~

После перезапуска проверить:

    p610_local_audio.running = true
    p610_local_audio.standby_state = ready
    p610_local_audio.provider_healthy = true

## Как должна работать фраза

Правильный сценарий:

    Окей Набу, какая сегодня погода?

Не нужно специально ждать звукового сигнала после Набу.

Система делает следующее:

1. локально ловит Okay Nabu;
2. хранит небольшой pre-roll;
3. около 0.9 секунды смотрит, продолжается ли команда;
4. если пользователь продолжает говорить — звук активации вообще не играет;
5. команда сразу идёт в Gemini;
6. если пользователь после wake-word замолчал — тогда можно проиграть обычный сигнал активации.

Это сделано, чтобы короткое слово вроде «погода» не терялось за звуком активации.

## Warm standby

Gemini WebSocket держится заранее готовым, чтобы не тратить подключение после каждого wake-word.

При этом в standby микрофон P610 обрабатывается локально. Сырой PCM не отправляется в Gemini до пробуждения.

Gemini может периодически сам закрывать долго простаивающее соединение кодом 1008. Это не обязательно авария: система быстро переподключается.

В Pipecat 1.4.0 был неприятный сценарий, когда три нормальных idle reconnect подряд могли ошибочно накопиться как 1/3 -> 2/3 -> 3/3 и стать fatal. В этом проекте есть build-time patch, который не даёт нормальным долгоживущим idle-сессиям накапливать такой false fatal.

## Задержка ответа

Если ответ приходит через 8-20 секунд, нельзя сразу обвинять Gemini. Нужно разбить задержку:

- wake -> конец команды;
- конец команды -> закрытие VAD turn;
- turn -> tool call;
- длительность tool call;
- tool result -> первый PCM;
- PCM -> реальное воспроизведение.

Для этого в проекте есть полный audio debug.

## Запись сессии для дебага

При включённом debug сохраняются:

- mic_raw.wav — что услышал физический микрофон;
- gemini_input.wav — что реально отправилось в Gemini;
- assistant_raw.wav — что вернул Gemini;
- assistant_played.wav — что реально ушло в PulseAudio/P610;
- mix_stereo.wav — синхронный микс микрофона и ассистента по разным каналам;
- timeline.json — wake, cue, первый звук, gaps, interruption, Stop, ошибки и закрытие сессии.

Хранение по умолчанию — 24 часа. Потом записи удаляются автоматически.

## Если звук дёргается

Система считает промежутки между PCM-фреймами:

- больше 100 мс;
- больше 200 мс;
- больше 500 мс;
- максимальный gap.

Если дырки уже есть в raw-выходе Gemini, проблема скорее в сети/proxy/provider.

Если raw ровный, а assistant_played ломается — смотреть pacat/PulseAudio/P610.

## Если колонка как будто перебивает сама себя

Нужно смотреть mix_stereo.wav и время provider interruption.

Возможные причины:

- пользователь реально заговорил;
- микрофон услышал собственный динамик;
- в Gemini попал wake-cue;
- короткий шум был распознан как речь;
- VAD ошибочно открыл новый user turn.

Отключать микрофон на время ответа нельзя без необходимости, потому что тогда пропадёт настоящий full duplex и barge-in.

## Stop

Во время активного разговора Stop ловится локально.

После Stop:

1. текущий ответ прерывается;
2. проигрывается звук завершения;
3. текущий worker закрывается;
4. сразу запускается новая свежая warm standby-сессия.

## Браузер

Для доступа к микрофону нужен HTTPS либо localhost.

Минимальная Lovelace-карточка:

~~~yaml
type: custom:pipecat-assist-card
name: Pipecat Assist
~~~

Если есть отдельный HTTPS-домен, можно указать secure_host.

## Обновления

Перед обновлением upstream-образа обязательно:

- изучить release notes;
- проверить версию Pipecat;
- проверить совместимость двух patch-скриптов;
- запустить тесты;
- собрать image;
- сделать rollback-копию;
- после обновления проверить реальный browser turn и реальный P610 turn.

Не надо обновлять working voice stack вслепую только потому, что появилась новая версия upstream.
